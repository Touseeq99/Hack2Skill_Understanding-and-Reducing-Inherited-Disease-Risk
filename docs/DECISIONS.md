# Architectural & Implementation Decisions

This document records key decisions, tradeoffs, and resolutions between the Architecture PDF (`Inherited_Disease_Risk_Solution_Architecture.pdf`) and the Prompt specification. Where the build brief and the PDF differ, the choice is recorded here with its clinical or engineering rationale.

| ID | Topic | Architecture PDF | Prompt Specification | Decision & Rationale |
|---|---|---|---|---|
| DEC-001 | Encryption Mechanism | Suggests `pgsodium` / Supabase Vault / HashiCorp Vault. | "Do NOT use pgsodium. Use an Encryptor interface with application-level AES-GCM and per-record keys (cryptography package)." | Implemented Python `Encryptor` interface using standard `cryptography.hazmat.primitives.ciphers.aead.AESGCM` with 256-bit per-record keys derived/managed securely. No database-level proprietary extensions needed. |
| DEC-002 | Database & Auth Infrastructure | Suggests Supabase (cloud or local self-hosted multi-container). | "Postgres in Docker with Row-Level Security (Supabase locally if easy, otherwise plain Postgres)." | Use pure PostgreSQL 16 container with native Row-Level Security (RLS) policies using Postgres session variables (`app.current_user_id`, `app.current_role`). Clean, lightweight, zero vendor lock-in, reliable on Docker Compose. |
| DEC-003 | Frontend Stack (User App & Counsellor Portal) | Proposes Flutter + `flutter_localizations`. | "Flutter user app + counsellor web portal with RTL Arabic and icon arrays (CustomPainter), or React if Flutter is unavailable." | Flutter is not pre-installed in the build environment. Built responsive single-file HTML/JS web apps (served by FastAPI) with full RTL Arabic support, DOM icon arrays, browser speech playback, and mobile-friendly design. |
| DEC-004 | T3 Triage Trigger for `possible_affected` | PDF table (Page 4/5) marks two P/LP recessive variants directly as T3. | Prompt states: "Two P/LP in the same AR gene (homozygous or compound het) -> 'possible_affected', T2 by default; T3 only if pregnant, or a distress signal fired, or the user reports symptoms (configurable flag)." | Follow prompt: `possible_affected` classifies to T2 by default, escalating to T3 if pregnant, distress detected, or symptoms reported. |
| DEC-005 | Natural Frequencies vs Percentages | Notes icon arrays and natural frequencies. | "Always output natural frequencies ('1 in 4') plus icon-array data; never percentages alone." | Output natural frequency strings (e.g. "1 in 4", "1 in 2") alongside explicit icon-array structured data (total, highlighted, categories) in all engine and template responses. |
| DEC-006 | Booking System | Recommends self-hosted Cal.com. | "Simple internal scheduler for booking" (or Cal.com). | Implemented built-in internal appointment scheduling engine with slot availability, counsellor filters (language, gender), booking status, and video/in-person options within the API and portal. Avoids fragile external Cal.com multi-service dependencies. |
| DEC-007 | Outcomes & Analytics Dashboard | Suggests Metabase / PostHog self-hosted. | "Built-in dashboard page or Metabase." | Implemented rich built-in analytics dashboard delivering exact metrics (comprehension uplift, uptake, referral SLAs, equity splits, zero unauthorized reads). Does not track cancelled marriages or single reproductive choices. |
| DEC-008 | Anonymous Family Notice | Generic relative notification. | Adds: "warn the sender that the choice of relatives may reveal who sent it; never include the sender's identity or result." | In app and API, explicit warning prompt displayed before sending notice. Stored in DB with hashed/hidden sender ID; message recipient sees only generic recommendation. |
| DEC-009 | Couple-Match Consent Notice | Basic consent grant. | Adds: "Couple-match consent screen must state that 'no shared gene' reveals a little about the partner." | App consent UI explicitly states: choosing couple matching means learning whether or not the partner carries variants in screened genes. |
| DEC-010 | LLM Adapter & Fallback | Local Ollama / hosted Gemini. | Must work fully in "template-only" mode with no LLM; strict validator checks for number drift, disclaimers, banned phrases, reading level. | Implemented pluggable LLM adapter interface (`TemplateOnlyAdapter`, `OllamaAdapter`, `GeminiAdapter`). Validator falls back immediately to approved pre-translated clinical templates upon any rule failure or LLM absence. |
| DEC-011 | Counsellor Queue & Bilingual Support Architecture | Static frontend mocks in prototype | Real database-driven triage cases and instant bilingual switching | Replaced frontend mock queue with live `/api/portal/queue` and `/api/portal/cases/{case_id}` endpoints connected directly to SQLite triage records and couple links. Built full bilingual dictionary engines in `app/index.html`, `portal/index.html`, and `portal/dashboard.html` ensuring 100% of medical and UI copy renders dynamically in Arabic (RTL) and English (LTR). |
